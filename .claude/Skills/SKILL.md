# 測試執行技能

這份技能提供「執行測試」的判斷邏輯，分成三部分：測試類型判斷、框架偵測慣例、失敗回報規範。

## 一、Smoke Test vs 完整 AutoTest

| 類型 | 用途 | 適用時機 |
|---|---|---|
| Smoke Test | 快速驗證基本功能沒有明顯壞掉（能不能啟動、核心路徑能不能跑通） | 小範圍修改後的快速檢查、部署前的最後把關 |
| 完整 AutoTest | 全面覆蓋既有測試套件，包含單元測試、整合測試 | 較大範圍修改、正式提交前、CI 流程中 |

沒有明確指定時，預設策略：小範圍修改（單一函式/元件）先跑 Smoke Test，若牽涉核心邏輯或多個模組，直接跑完整 AutoTest。

## 二、常見測試框架偵測慣例

執行前先判斷專案使用的測試框架，常見線索：
- `package.json` 有 `test` script、`jest`/`vitest`/`mocha` 相關依賴 → Node.js 生態系
- `pytest.ini`、`pyproject.toml` 內有 `[tool.pytest]`、或有 `test_*.py` 檔案 → Python pytest
- `go.mod` 存在且有 `_test.go` 檔案 → Go 內建 `go test`
- 找不到明確測試設定時，先讀專案 README 或 CI 設定檔（如 `.github/workflows/`）確認實際使用的測試指令，不要用猜測的框架硬套指令

## 三、失敗回報格式規範

每筆失敗案例務必包含：
1. 測試名稱/描述
2. 具體錯誤訊息（不省略、不改寫成模糊敘述）
3. 發生位置（檔案路徑與行號，若測試框架有提供）
4. 若為斷言失敗，附上「預期值」與「實際值」的對照

## 四、輸出前檢查清單

- [ ] 已正確偵測專案使用的測試框架，而非套用猜測的指令
- [ ] 測試策略（Smoke／完整）符合修改範圍或呼叫方指定
- [ ] 每筆失敗都附完整錯誤訊息與位置，未簡化省略
- [ ] 沒有為了讓測試通過而修改任何程式碼或測試斷言
