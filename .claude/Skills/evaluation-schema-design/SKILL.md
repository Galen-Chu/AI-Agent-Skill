# 評測 Schema 與驗收判定技能

這份技能提供「評測／驗收」相關的判斷邏輯，分成三部分：Schema 結構檢查、判定分級規則、可追溯性格式規範。

## 一、一份完整的評測 Schema 該有的欄位

Schema 由呼叫方（需要領域判斷的一方）提供，本技能只負責檢查其**結構**是否完整，不介入其**內容**（指標本身該設什麼，是呼叫方的領域判斷）。每個指標至少要包含：

| 欄位 | 說明 | 缺少的後果 |
|---|---|---|
| 名稱 | 指標識別 | 報告無法對應追蹤 |
| 測量方式 | 怎麼從目標輸出量出這個指標的值（不能只寫「品質好不好」這種無法操作的描述） | 評測者只能主觀猜測，結果不可重現 |
| 通過門檻 | 量化或明確的通過/不通過邊界 | 判定淪為主觀感覺，同一輸出換人評會得到不同結果 |
| 關鍵度 | 是否為「不過此項則整體判定為不通過」的關鍵指標 | 無法計算整體判定，只能列出各項結果、無法彙總 |

Schema 缺少上述任一欄位時，判定為「結構不完整」，應退回呼叫方補齊，不代為腦補判定標準——腦補等於評測者自己決定了品質標準，違反「評測與被評測邏輯分離」的前提。

## 二、整體判定分級規則

| 判定 | 條件 |
|---|---|
| ✅ 通過 | 所有指標皆通過 |
| ⚠️ 部分通過 | 關鍵指標皆通過，但至少一項非關鍵指標不通過 |
| ❌ 不通過 | 至少一項關鍵指標不通過 |

沒有標示「關鍵度」的指標，預設視為關鍵指標（保守判定，避免漏掉真正重要的落差）。

## 三、可追溯性格式規範

每一筆判定都必須能回指到目標輸出的具體位置（行號、段落、資料筆數等），不能只給「不符合」的結論。這是「可追溯性驅動」評測的核心要求——沒有依據的判定，跟沒有判定一樣不可信。

落差描述格式：`<指標名稱>：<實際觀察> vs <通過門檻>（位置：<具體引用>）`

## 四、輸出前檢查清單

- [ ] Schema 若結構不完整，已回報缺漏而非代為補齊判定標準
- [ ] 每筆判定都附具體位置依據，沒有空泛結論
- [ ] 整體判定依「關鍵度」規則彙總，未標關鍵度的指標視為關鍵
- [ ] 未評判 Schema 本身的內容合理性（那是呼叫方的領域判斷）
